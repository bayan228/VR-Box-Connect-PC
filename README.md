# VR Box Connect: MONO и экспериментальный SteamVR
# ВСЕ НАПИСАНО С ИСПОЛЬЗОВАНИЕМ ИИ!!!
PC-to-Android стример для VR-бокса. MONO показывает одно изображение обоим
глазам; экспериментальный SteamVR-режим передаёт независимые половины SBS
из композитора и возвращает ориентацию телефона в виртуальный HMD.
Это **не готовая замена игровому VR-шлему**: физический телефон, игры и
motion-to-photon задержка ещё требуют проверки.

## Запуск двойным кликом

Готовые батники находятся **в корне проекта**, рядом с этим README. Сборки EXE,
DLL и APK должны уже существовать; батники ничего не скачивают и не пересобирают.
Их можно запускать из Проводника или ярлыком, текущая папка терминала не важна.

| Файл | Что делает |
|------|------------|
| **`START_VR.bat`** | Проверяет файлы, находит установленный SteamVR, регистрирует драйвер только при необходимости, запускает сервер `--steamvr`, дожидается его готовности и запускает SteamVR. |
| `TEST_STEREO.bat` | Запускает разные тестовые картинки для глаз, без SteamVR и без захвата рабочего стола. |
| `DESKTOP_MONO.bat` | Передаёт основной рабочий стол после подключения телефона. Это плоское видео, не VR-режим игры. |
| `OPEN_APK.bat` | Открывает Проводник с выделенным `app-debug.apk` для установки/обновления на телефоне. |
| `STOP_SERVER.bat` | Завершает только сервер, запущенный батниками из этой папки. Игру, SteamVR и серверы, запущенные вручную, не закрывает. |

Обычный порядок:

1. Один раз установить свежий APK на телефон через файл, показанный `OPEN_APK.bat`.
2. Подключить ПК и телефон к одной доверенной сети, закрыть ранее запущенный SteamVR.
3. Дважды нажать **`START_VR.bat`**. Вручную запускать сервер и SteamVR не нужно.
4. Оставить окно батника открытым. В нём видны `PC IPv4` и текущий `Pairing PIN`.
   На телефоне ввести их и нажать `Connect`.
5. Запустить нужную VR-игру на ПК. На телефоне использовать `Recenter in 3s`,
   затем `Hide`, чтобы убрать панели.
6. После игры нажать `Disconnect` на телефоне и закрыть игру/SteamVR.
   Сервер остановить через `Ctrl+C` в его окне либо двойным кликом `STOP_SERVER.bat`.

Регистрация идёт через штатный `vrpathreg.exe`, без ручной перезаписи JSON.
Существующая регистрация этой же сборки сохраняется. Если зарегистрирована
другая сборка, есть дубликаты или уже запущен сервер/SteamVR, батник сообщает
об этом и не закрывает чужие процессы. Путь к драйверу автоматически переводится
в короткую форму Windows 8.3; жёстко заданного имени пользователя нет.
Если на диске отсутствуют короткие имена для пути с кириллицей, требуется ASCII-путь.

При ошибке окно остаётся открытым. `STOP_SERVER.bat` предназначен для быстрого
завершения своего PC-процесса; штатное завершение через `Ctrl+C` также доступно.
Батники не отключают брандмауэр, не сохраняют PIN в файлы и не меняют постоянную
политику PowerShell. При запросе Windows разрешить сервер только в частной сети.
Установка APK, `Connect`/`Recenter` на телефоне и выбор игры остаются ручными:
автоматического доступа к телефону или управления неизвестной игрой нет.

Безопасная диагностика из PowerShell, без запуска сервера/SteamVR и изменения регистрации:

```powershell
.\START_VR.bat -CheckOnly
```

Проверка настоящего сервера только на этом ПК, с автоматической остановкой:

```powershell
.\TEST_STEREO.bat -Loopback -RunSeconds 2
```

Обычный двойной клик не включает `-Loopback`: телефон подключается по LAN.
Общий сценарий находится в `scripts/launch.ps1`. Автотест `launcher_tests`
проверяет батники на подставных EXE, включая пробелы/кириллицу/спецсимволы в пути,
порядок запуска, отсутствие повторной регистрации, ошибки и адресную остановку.
Он не запускает настоящий SteamVR и не изменяет глобальный список драйверов.

## Что реализовано

- Windows: захват основного экрана через DXGI Desktop Duplication, масштабирование
  с сохранением пропорций, NV12 и программный H.264 Media Foundation.
- Отдельный режим `--test-pattern`: движущийся шаблон без захвата рабочего стола.
- `--stereo-test-pattern`: разные изображения глаз для проверки SBS без SteamVR.
- `--steamvr`: виртуальный HMD, перехват стереокадра композитора D3D11,
  3DoF от IMU, Recenter, настраиваемые IPD и вертикальный FOV. Нет desktop fallback.
- TCP-сессия с PIN, проверкой параметров, привязкой UDP-портов телефона,
  сообщением об ошибках и повторным подключением после отключения.
- UDP-фрагментация AU, CRC16-CCITT-FALSE, запрос нового IDR, timing/RTT и приём IMU.
- Android: подключение по числовому локальному IPv4 и PIN, ограниченная сборка
  кадров, MediaCodec -> SurfaceTexture -> OpenGL, вывод для двух глаз и метрики.
- Последнее подключение сохраняется на телефоне: повторное подключение,
  закрепление/замена и удаление; IPv4 и PIN хранятся зашифрованно.
- Программная калибровка размера, сведения, положения и перспективного наклона
  изображений; раздельный баланс глаз, сохранение настроек и сетка без сервера.
- Закрытие сессии при уходе приложения в фон. Ненужный foreground service удалён.
- C++-тесты протокола, head pose, IPC, GPU shared textures и H.264 encode/decode;
  сетевые smoke-тесты MONO/SBS/SteamVR и Kotlin-тесты протокола, SBS и геометрии.
- Батники для запуска VR, тестового стерео, MONO, доступа к APK и остановки своего сервера.

## Ограничения

- Только seated 3DoF: нет отслеживания перемещения головы, VR-контроллеров и звука.
  Положение головы фиксировано на высоте 1.2 м, это не измерение роста/пола.
- IMU управляет виртуальным HMD только в `--steamvr`; MONO не управляет
  камерой обычной игры и не превращается в настоящее стерео.
- Кодировщик на ПК программный. NVENC/аппаратный MFT и GPU zero-copy ещё не внедрены.
- MONO по умолчанию: 1280x720, 30 fps, 8 Mbit/s; SteamVR: 1280x720 SBS,
  60 fps, 12 Mbit/s, IPD 64 мм, вертикальный FOV 75 градусов. Это заданные
  параметры, не обещание достигнутой частоты. Геометрия и fps HMD требуют
  перезапуска SteamVR и переподключения, а не перенастройки на лету.
- Поворот головы и видео пока не образуют измеренный motion-to-photon тракт.
  RTT не равен задержке изображения; 10..33 мс и отсутствие укачивания не гарантируются.
- Отдельный аппаратный курсор DXGI не дорисовывается. Защищённые окна/видео могут
  быть чёрными; блокировка сеанса или смена дисплея может потребовать переподключения.
- Пользователь подтвердил работу видеопотока на телефоне, но обнаружил инверсию
  поворотов. Знак landscape-преобразования исправлен на ПК; исправленные направления
  ещё нужно проверить на телефоне. Оптика и задержка остаются непроверенными.
- Калибровка ручная: нет проверенного заводского профиля SC-G и загрузки
  Cardboard QR. Цифровой наклон меняет геометрию картинки, не физический фокус линз.

## Первый тест на телефоне: без рабочего стола

**На телефон переносится только** `android-client/app/build/outputs/apk/debug/app-debug.apk`.
**На ПК запускается** `pc-server/build/Release/vrbox_server.exe`. JDK, Android SDK,
`.tools`, EXE и папку проекта на телефон переносить не нужно. Для установки этого
APK нужен Android 11 или новее; Android Studio и Java на телефоне не нужны.

1. Подключить ПК и телефон к одной доверенной локальной сети. Желательно Wi-Fi
   5 ГГц; ПК может быть подключён кабелем к тому же роутеру. Гостевая сеть и
   изоляция клиентов могут запрещать соединение между устройствами.
2. Подключить телефон по USB, выбрать режим передачи файлов и скопировать APK
   в папку `Download` телефона. Открыть файл в файловом менеджере и установить
   `VR Box Client` или подтвердить обновление уже установленной debug-сборки.
   При запросе Android разрешить установку из этого источника для используемого
   файлового менеджера; после установки разрешение можно отключить.
   Отладка по USB и `adb` для этого способа не нужны.
3. Открыть PowerShell в папке проекта на ПК и выполнить:

```powershell
.\pc-server\build\Release\vrbox_server.exe --test-pattern
```

4. Оставить консоль открытой. Проверить строку `Source: test pattern`, затем найти
   `PC IPv4: ...` и `Pairing PIN: ...`. Если Windows запрашивает доступ через
   брандмауэр, разрешить сервер только в доверенной частной сети, не отключая
   брандмауэр целиком.
5. Открыть `VR Box Client`. В поле `PC IPv4` ввести **только адрес из строки
   сервера**, например `192.168.1.10`, **без двоеточия, порта и `http://`**.
   Порт TCP `8765` уже задан автоматически, поэтому отсутствие `:` на клавиатуре
   нормально. В `Pairing PIN` ввести все шесть цифр текущего PIN из консоли,
   включая начальные нули, и нажать `Connect`.
6. Сначала держать телефон в руках, без VR-бокса. Должна появиться движущаяся
   тестовая картинка, одинаковая в обеих половинах экрана; сверху должно быть
   `Test pattern / MONO`, а `Decoded` и `Rendered` должны показывать ненулевой fps.
   Проверить работу 30-60 секунд, нажать `Disconnect`, затем подключиться снова.
   Для завершения остановить сервер через Ctrl+C.

**Не запускать EXE двойным кликом для первого теста:** без `--test-pattern`
сервер после подключения передаёт основной рабочий стол. Режим `--test-pattern`
вообще не захватывает экран. В MONO и тестовых шаблонах повороты головы
не управляют картинкой или игрой.

Если подключение не удалось:

- `0.0.0.0` в строке `Server ready` означает прослушивание всех интерфейсов,
  это не адрес для ввода в APK. `127.0.0.1` доступен только на самом ПК, не с телефона.
- Если показано несколько `PC IPv4`, выбрать адрес Wi-Fi/Ethernet той же локальной
  сети, что и телефон, а не VPN или виртуального адаптера. Сервер не может заранее
  определить, к какой из нескольких сетей подключён телефон. Адрес можно сверить
  через `ipconfig`; после смены сети перезапустить сервер и взять новый адрес/PIN.
- При тайм-ауте проверить общую сеть, отсутствие изоляции клиентов и разрешение
  для EXE в брандмауэре. Порты сервера: TCP `8765`, UDP `8766..8768`.
  Не настраивать проброс портов в интернет.
- Ошибка PIN требует текущего PIN из работающей консоли, не PIN из примера или
  прошлого запуска. После сворачивания приложения сессия закрывается, нужно
  подключиться заново.

## Последнее подключение (с APK 0.1.1)

Хранится одна запись: IPv4, PIN и признак закрепления. После успешного подключения
и согласования видео запись появляется в блоке `Last connection`. Неудачная
попытка подключения не заменяет сохранённый ПК. При следующем запуске приложения
поля восстанавливаются; соединение само не начинается, нужно нажать кнопку.

- `Connect to last` подключает к последней записи без повторного ввода IPv4/PIN.
  Для закреплённой записи кнопка называется `Connect to pinned`.
- `Pin` закрепляет показанную запись. Успешное подключение к другому IPv4 её
  больше не заменит. `Unpin` снова разрешает автоматически запоминать последний ПК.
- Чтобы закрепить новое подключение, заполнить поля `PC IPv4` и `Pairing PIN`,
  затем нажать `Pin as last`, если записи ещё нет, или
  `Replace saved with these fields`, если она есть. Это явно заменяет старую
  запись и закрепляет новую; проверяется формат полей, но подключение этой кнопкой
  не запускается. `Connect` под полями подключает с введёнными данными.
- `Delete` удаляет запись из хранилища и очищает поля. После закрытия и повторного
  открытия приложения удалённая запись не должна появляться снова. Новое успешное
  подключение после удаления можно сохранить автоматически или закрепить вручную.

**PIN сервера обычно меняется при его перезапуске.** Сохранённая запись не отменяет
эту проверку: нужно заменить PIN в поле на новый из консоли ПК. После успешного
подключения к тому же IPv4 новый PIN запоминается, в том числе для закреплённого ПК.
При смене IPv4 закреплённую запись нужно явно заменить.

IPv4 и PIN защищены AES-256-GCM, ключ хранится в Android Keystore. Запись размещена
во внутреннем `noBackupFilesDir`, не переносится в резервные копии приложения;
PIN не записывается в saved-state Bundle и не показывается в карточке открытым
текстом. Сетевой трафик при этом по-прежнему не зашифрован: использовать только
доверенную LAN. При ошибке чтения записи доступны ручное подключение, её удаление
и явная замена; незашифрованного запасного способа хранения нет.

Проверка на телефоне после установки обновления поверх предыдущего APK:

1. Подключиться к серверу с `--test-pattern`, выйти из приложения и открыть его
   снова, не перезапуская сервер. Проверить заполненные поля и `Connect to last`.
2. Закрепить запись через `Pin`; проверить её сохранение после перезапуска APK.
   При необходимости заменить её заполненными полями через `Replace saved with these fields`.
3. Нажать `Delete`, полностью закрыть и снова открыть приложение. Запись и поля
   должны оставаться пустыми до нового подключения или ручного закрепления.

## Калибровка изображения в APK 0.1.2

Настройки предназначены для просмотра с **ровно закреплённым телефоном и закрытым
держателем**, а не для постоянного физического наклона телефона. Все корректировки
ниже выполняются программно. На первом запуске размер установлен в 80%, расстояние
между центрами картинок в 85% от прежнего, искажение линз выключено. Это стартовые
значения для подбора, не измеренный профиль глаз пользователя или модели SC-G.

1. Установить новый APK поверх предыдущего. На экране подключения нажать
   `Calibrate headset`. Появится одинаковая сетка с центральным крестом, кругом
   и рамкой для каждого глаза. **ПК, сервер, IPv4 и PIN для этого режима не нужны.**
2. Сначала уменьшить `Image size`, например до 70-80%, если виртуальные экраны
   кажутся большими. `Image spacing` меняет расстояние между центрами: меньшее
   значение сближает картинки. Проценты этого поля **не являются IPD в миллиметрах**.
3. `Image height` перемещает обе картинки вверх/вниз. Нажать `Fine alignment`,
   если требуется дополнительное совмещение. `Vertical eye balance` сдвигает
   картинки по вертикали навстречу друг другу: положительное значение поднимает
   левую относительно правой.
4. `Tilt up / down` и `Tilt left / right` регулируют перспективный наклон
   виртуального экрана. Это не просто поворот плоской картинки: меняется
   перспективное соотношение противоположных краёв. Подбирать маленькими шагами,
   меняя только один параметр за раз, не наклоняя сам телефон.
5. `Image rotation` поворачивает оба экрана. `Eye rotation balance` регулирует
   разницу их поворотов, `Eye size balance` разницу размеров. Положительные
   значения баланса означают, что левое изображение больше или повёрнуто сильнее
   против часовой стрелки. `Horizontal position` смещает обе картинки вместе.
6. Нажать `Hide` или `Hide controls`, затем оценивать совмещение центрального
   креста, круга и краёв. **Все служебные панели полностью скрываются**, чтобы
   разные надписи перед глазами не мешали совмещению. Касание экрана возвращает
   управление. У каждого ползунка есть кнопки `-` и `+` для точной подстройки.
7. `Lens distortion` сначала оставить равным 0. Только после совмещения можно
   подбирать коррекцию изгиба линий. Коэффициент не привязан к заводским линзам
   SC-G, поэтому максимальное значение не означает лучшую настройку.
8. Настройки сохраняются после отпускания ползунка/нажатия кнопок, при завершении
   калибровки и уходе приложения в фон. `Done` возвращает к подключению. Затем
   подключиться к ПК; тот же профиль применяется к видео. `Reset` сбрасывает
   только геометрию к стартовым значениям, не удаляет сохранённые IPv4 и PIN.

Если на больших значениях смещений/наклона картинка вышла бы за свою половину,
приложение дополнительно уменьшает **обе** картинки общим коэффициентом.
Он показывается как `Safety fit`; это предотвращает разную обрезку глаз и
попадание изображения в соседнюю половину. Параметры хранятся отдельно от
сохранённого подключения и восстанавливаются после перезапуска APK.

Во время сетевой сессии те же настройки доступны через `Display`, а `Test grid`
временно заменяет отображаемое видео сеткой. **Такое переключение не останавливает
передачу и захват на сервере**; `Rendered` при показе сетки не считается как вывод
видеокадров. Для калибровки вообще без захвата рабочего стола использовать
отдельный `Calibrate headset` до подключения либо сервер с `--test-pattern`.

Проверка на устройстве: добиться совмещения при закрытом держателе, выйти из
приложения и убедиться, что настройки восстановились; проверить `Hide`/касание,
`Reset`, возврат из сетки к видео и повторное подключение к сохранённому ПК.
Программные коррекции не заменяют резкость линз и не превращают MONO в объёмное
стерео. При напряжении глаз или стойком двоении прекратить тест, не заставляя
глаза сходиться усилием.

## SBS без SteamVR

```powershell
.\pc-server\build\Release\vrbox_server.exe --stereo-test-pattern
```

Подключение по IPv4/PIN такое же, как у MONO. Текущий APK показывает каждую
половину SBS только своему глазу и сохраняет пропорции одного глаза. Разные
картинки шаблона проверяют порядок глаз, но не имитируют игровую сцену.
Старый APK без поддержки `stereo_sbs` будет явно отвергнут, а не получит
ошибочно продублированную стереопару. Рабочий стол этот режим не читает.

## Экспериментальный SteamVR

Нужны установленный SteamVR, собранный драйвер и свежий APK. Сначала завершить
SteamVR. Пакет находится в `pc-server/build/steamvr/vrbox`, DLL внутри
`bin/win64/driver_vrbox.dll`. Главный батник `START_VR.bat` выполняет регистрацию
автоматически при необходимости. Ниже ручной вариант для стандартного расположения SteamVR:

```powershell
$vrpathreg = "C:\Program Files (x86)\Steam\steamapps\common\SteamVR\bin\win64\vrpathreg.exe"
$package = (Resolve-Path ".\pc-server\build\steamvr\vrbox").Path
$package = (& cmd.exe /d /c ('for %I in ("{0}") do @echo %~sI' -f $package)).Trim()
if ($package -match '[^\x00-\x7F]') { throw 'SteamVR needs an ASCII package path; use an ASCII build directory.' }
& $vrpathreg adddriver $package
```

Команда меняет список внешних драйверов SteamVR, не устанавливает системный
драйвер Windows. Для отмены после закрытия SteamVR: `& $vrpathreg removedriver $package`.
Короткий путь 8.3 нужен из-за кириллицы в пути проекта: текущий runtime при
путях config/log с кириллицей возвращал `Init_NoLogPath`; ASCII-пути сработали.
При другом расположении SteamVR нужно использовать его `vrpathreg.exe`.
Во время описанных ниже испытаний глобальная регистрация не выполнялась.

Порядок запуска:

1. Запустить сервер, до SteamVR:

```powershell
.\pc-server\build\Release\vrbox_server.exe --steamvr --width 1280 --height 720 --fps 60 --bitrate-kbps 12000 --ipd-mm 64 --fov-y 75
```

2. Запустить SteamVR без другого активного HMD. Проверить, что найден
   `VR Box Phone 3DoF`, а дополнение `vrbox` не отключено в SteamVR.
3. Подключить APK по IPv4/PIN. IMU и control запускаются до первого кадра:
   ожидание композитора не должно отключать соединение. Смотреть прямо и
   использовать `Recenter`; подтверждение приходит с сервера, а не имитируется UI.
4. Для дальнейших испытаний выбирать seated-игру с клавиатурой/геймпадом или
   рулём, не требующую VR-контроллеров. При необходимости отдельно настроить
   seated origin/комнату в SteamVR или игре. Проверки конкретных игр пока нет.

После исправления инверсии поворотов обновлён только сервер
`pc-server/build/Release/vrbox_server.exe`. Переустанавливать APK или заново
регистрировать DLL не требуется. Закрыть сервер и SteamVR, запустить
`START_VR.bat`, переподключить телефон и выполнить `Recenter in 3s`, глядя вперёд.

Проверять нужно направление взгляда: при повороте головы вправо становятся видны
объекты справа, при подъёме головы видна область выше. Уже видимый неподвижный
объект при этом смещается в противоположную сторону на экране, это нормально
для VR. Исправление не зеркалит видео и не меняет порядок глаз.

IPD здесь задаёт расстояние между виртуальными камерами. Ползунок `Image spacing`
на телефоне меняет размещение изображений и не является IPD в миллиметрах.
При отсутствии IMU старше 250 мс шлем перестаёт сообщать валидный трекинг;
Recenter без свежей pose возвращает отказ. Без композитора видео остаётся в
ожидании, рабочий стол вместо него не передаётся. Сначала проверять телефон
в руках, затем короткими сеансами сидя; при двоении или дискомфорте остановиться.

## Сборка ПК

Все команды ниже выполняются из папки проекта. Требуются Windows 10/11,
CMake 3.20+, MSVC с C++20 и Windows SDK. В Windows N могут потребоваться
мультимедийные компоненты ОС; проект не устанавливает их автоматически.

```powershell
cmake -S .\pc-server -B .\pc-server\build -DVRBOX_BUILD_STEAMVR_DRIVER=ON -DBUILD_TESTING=ON
cmake --build .\pc-server\build --config Release
ctest --test-dir .\pc-server\build -C Release --output-on-failure
```

Результат: `pc-server/build/Release/vrbox_server.exe` и пакет
`pc-server/build/steamvr/vrbox`. Лицензии JSON/OpenVR включены в соответствующие
выходные каталоги. OpenVR SDK 2.15.6 закреплён по commit и SHA256; первоначальная
загрузка требует интернета. Для сборки без пакета драйвера доступен
`-DVRBOX_BUILD_STEAMVR_DRIVER=OFF`; MONO от SteamVR не зависит.

Сначала проверить тестовую картинку:

```powershell
.\pc-server\build\Release\vrbox_server.exe --test-pattern
```

После проверки, для передачи **содержимого основного рабочего стола**:

```powershell
.\pc-server\build\Release\vrbox_server.exe
```

Сервер показывает шестизначный PIN и строки `PC IPv4` для активных локальных
IPv4, допустимых клиентом. Отключённые/неготовые адреса и loopback не предлагаются
для подключения телефона. При явном `--bind` показывается только заданный адрес;
для `--bind 127.0.0.1` выводится предупреждение о режиме только для ПК.
В приложении нужно ввести IPv4 без `:8765` и текущий PIN. Захват в desktop-режиме
начинается только после успешного подключения. Завершение: Ctrl+C.
Список параметров доступен через `--help`, например:

```powershell
.\pc-server\build\Release\vrbox_server.exe --width 1280 --height 720 --fps 30 --bitrate-kbps 8000
```

## Сборка Android

Проект: Android 11+ (minSdk 30), compile/target SDK 34, AGP 8.3.0,
Kotlin 1.9.22, Gradle 8.6, JDK 17. Wrapper использует SDK только из
`.tools/android-sdk` внутри проекта, не обращаясь к внешнему `ANDROID_HOME`.
Для APK нужны Android SDK Platform 34 и Build Tools 34.0.0. Установка SDK
и принятие его лицензии выполняются отдельно; автоматическая установка отключена.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\android-client\build.ps1 assembleDebug testDebugUnitTest lintDebug
```

`build.ps1` докачивает фиксированный portable Microsoft JDK 17.0.21.0.2
в `.tools`, проверяет опубликованный SHA256 и вызывает Gradle Wrapper.
Он не устанавливает Java глобально и не меняет
системные переменные. Кэши Gradle, временные файлы, Android home и debug key
тоже размещены в `.tools` внутри проекта. Загрузка инструментов и зависимостей
требует интернета; сама сессия стриминга работает без него.

При обрыве загрузки повторить ту же команду. Для подготовки только JDK:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\android-client\build.ps1 --bootstrap-only
```

После подготовки JDK можно использовать `android-client/gradlew.bat` напрямую.
Результат сборки: `android-client/app/build/outputs/apk/debug/app-debug.apk`.
Это APK, подписанный локальным ключом **Android Debug**, для испытаний, а не
release-сборка с ключом для распространения. После пересборки нужно перенести
свежий APK на телефон и установить обновление: уже установленная копия сама не меняется.

Для проверки чистого Kotlin-кода SDK не нужен:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\android-client\build.ps1 --protocol-tests
```

Отдельная JVM-сборка `android-client/protocol-tests` использует исходные файлы
протокола, очередей, Annex B, проверки IPv4/PIN, шифрованного хранилища и геометрии
калибровки вместе с их unit-тестами, без копирования кода. Для принудительного повторного запуска
добавить `--rerun-tasks`. Отчёт: `android-client/protocol-tests/build/reports/tests/test/index.html`.
Это не сборка Android UI, MediaCodec или сенсоров и не испытание на устройстве.

В Windows не следует принудительно задавать `file.encoding=UTF-8` для Gradle
на JDK 17: Java launcher читает файлы аргументов тестовых процессов в системной
кодировке. Несовпадение ломает classpath с кириллицей. Wrapper и Gradle сохраняют
штатную кодировку JVM, не меняя настройки ОС; исходники остаются UTF-8.

## Сетевая проверка

В одном терминале запустить только синтетический сервер на loopback:

```powershell
.\pc-server\build\Release\vrbox_server.exe --test-pattern --bind 127.0.0.1 --pin 123456 --width 320 --height 240 --fps 30 --bitrate-kbps 500
```

В другом терминале, также из проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\pc-server\tests\session_smoke.ps1 -Pin 123456
```

Проверяются фрейминг TCP, отказ второму клиенту и неверному PIN, фрагменты
H.264 с SPS/PPS/IDR, timing, IMU и повторный запуск видео/IMU с новыми UDP-портами.
TCP-запрос и UDP NACK должны дать IDR раньше периодического GOP: обычный
плановый ключевой кадр больше не считается доказательством восстановления.
Для этого smoke-тест требует `--test-pattern`, GOP 1 с и не менее 4 fps.
Сам тест запрашивает видео, поэтому его нельзя запускать против desktop-режима.
Тесты CTest не захватывают экран: видео создаётся синтетически и проходит
обратно через нативный H.264-декодер.

Для SBS использовать сервер с `--stereo-test-pattern` и тот же smoke с `-Stereo`.
Для ожидания SteamVR использовать сервер с `--steamvr --bind 127.0.0.1 --pin 123456`
и smoke с `-SteamVR`, **без запущенного композитора**. Он проверяет живой control,
IMU, свежий/устаревший Recenter и отсутствие desktop fallback более 6 секунд.
`-SteamVR -ExpectCompositor` требует одновременно работающую настоящую VR-сцену
и дополнительно проверяет получение полного H.264 IDR композитора.

Последние результаты:

- CTest **6/6**: 37 проверок батников, 95 протокола, 916 head pose, 75 IPC и 97 HMD/GPU.
  Видео: по 12 encode/decode кадров в MONO, synthetic SBS и IPC SBS, с IDR
  на кадрах 0 и 6. Проверены цвета/порядок глаз, timestamp и отложенный запрос IDR.
- Инверсия yaw/pitch воспроизведена независимым тестом физических осей телефона.
  Исправлен знак компенсации `ROTATION_90`/`ROTATION_270`; проверены направления,
  гироскоп, roll, составные повороты и сохранение Recenter. Старый код этот тест
  не проходил. Сервер пересобран, APK и DLL не менялись.
- `TEST_STEREO.bat -Loopback -RunSeconds 2` запущен с настоящим EXE из другой
  рабочей папки: сервер стал готов и штатно завершился, SteamVR не запускался.
  `START_VR.bat -CheckOnly` подтвердил существующую регистрацию без её изменения.
- Loopback MONO: **98 проверок**, synthetic SBS: **101**, SteamVR без композитора:
  **131**. Число проверок зависит от полученных сообщений и фрагментов.
- Реальный SteamVR **2.17.9**, NVIDIA RTX 3050 Laptop GPU: загрузка DLL, HMD,
  независимые texture submission двух глаз, callbacks композитора и H.264 по UDP.
  В контрольном прогоне получены **44 кадра 1280x720**, 45 валидных pose;
  **20 кадров** подтвердили красный левый и зелёный правый глаз. Сетевой тест
  завершился с **574 проверками**.
- Исправлена реальная причина отсутствия кадров: redirect должен активироваться
  раньше HMD. Обратный порядок на этой версии SteamVR давал шлем и успешно
  принятые Submit, но не вызывал Present. Порядок регистрации покрыт тестом;
  фактическая активация и callbacks подтверждены логом `vrserver.txt`.
- Ручной scene probe и профиль находятся в игнорируемой `.build-tmp/steamvr-smoke`.
  Использован `VR_PATHREG_OVERRIDE`, отдельные config/log и ASCII-пути.
  Глобальный `openvrpaths.vrpath` не менялся. Сервер VR Box в сетевых испытаниях
  слушал только `127.0.0.1`, не захватывал рабочий стол и не требовал телефона.

Это проверка реального **PC-тракта**, не игрового запуска на устройстве.
Scene probe использовал тестовую IMU и raw tracking space без настройки комнаты.
Реальная Wi-Fi-сессия, Android MediaCodec/датчики, оптика, seated origin игры,

не установлено; runtime нельзя считать проверенным без оговорок.

## Безопасность

Использовать только доверенную локальную сеть. Трафик **не зашифрован**;
PIN предотвращает случайное подключение, но не защищает от перехвата в LAN.
Не настраивать проброс портов в интернет. Сервер слушает TCP 8765 и UDP
8766..8768; для испытаний только на ПК используйте `--bind 127.0.0.1`.
Проект не добавляет правила брандмауэра и не меняет системную конфигурацию.
